# Архитектура Gym21

Проверено по исходникам 8 сентября 2026 (O08); запуск и эксплуатационные ограничения — в [runbook](runbook.md).

## Компоненты

Клиент — TypeScript/Vite PWA с DOM-компонентами и CSS. `apps/client/src/main.ts` только подключает стили, service worker и lifecycle приложения. `ui/application.ts` собирает страницы `ui/pages/`, router, зависимости и обработчики; страницы освобождают ресурсы через lifecycle. Хранилище разделено на account repository, доменные операции, backup, чтения и sync coordinator.

Сервер — Express с маршрутизацией и middleware в `apps/server/src/http/`, Better Auth и PostgreSQL. Auth и доменные данные используют один pool. SQL-файлы `001`–`007` в `apps/server/migrations/` применяются под session advisory lock, каждый вместе с записью в журнале — в транзакции. Runtime не читает legacy JSON. Новое изменение схемы — новый SQL-файл, а не правка применённого.

`packages/contracts` содержит общие схемы и wire-типы; локальные поля клиента и SQL row-типы остаются на своих сторонах. Vite и серверный dev используют исходники, production Node — собранный пакет. Серверная сборка сначала собирает contracts.

## Данные и авторизация

После подтверждённого входа несекретный descriptor открывает IndexedDB соответствующего `storageKey` даже офлайн. Данные и deduplicated outbox изменяются одной транзакцией. Поколения outbox, версии сущностей, явные acknowledgements и cursor защищают изменения от устаревших ответов; конфликты сохраняются для восстановления. Sync protocol v1 использует ограниченные push-пачки и постраничный pull. Клиент автоматически повторяет временные ошибки и восстанавливает соединение по событию online.

Браузерный клиент использует для сетевой авторизации только HttpOnly cookie Better Auth: email/password, Passkey, Telegram Widget и проверенный Mini App initData. Descriptor не заменяет cookie. Незавершённый выход сохраняется между перезапусками и блокирует восстановление прежней сессии до завершения; явный выход блокирует автоматический TMA-вход. Dev-гость скрыт за dev-режимом и не требует серверной БД.

Backup merge/replace онлайн проверяет ревизию и применяется атомарно; офлайн разрешён только merge. Legacy CLI импортирует проверенный план одной PostgreSQL-транзакцией, сохраняя ownership, версии и tombstones. Подробности и ограничения — в runbook.

## Производные данные и эксплуатация

Дни считаются в IANA-зоне владельца, длительность — в секундах. Публичная статистика охватывает всю историю; недавняя активность — 14 активных дней, полная история — страницы до 100 подходов. Тепловая карта получает отдельные дни активности. AI требует синхронизированного snapshot с ожидаемой ревизией. Публичные чтения и AI-контекст ограничены; кэши инвалидируются по ревизиям. Локальный доменный кэш клиента всё ещё содержит всю историю: память и первоначальное чтение растут с её размером.

Docker обслуживает SPA/API через один origin; PostgreSQL по умолчанию не публикует порт. API образ содержит production-зависимости и работает без root. `/health` проверяет жизнь процесса, `/ready` — БД, миграции и готовность принимать запросы. Общие PostgreSQL rate limits/leases, таймауты и shutdown ограничивают нагрузку, но внешнее AI-вычисление может продолжиться после отмены. [TLS](../audit/postgres-tls.md), [лимиты](../audit/runtime-limits.md), [CSP и доступность](../audit/accessibility-csp.md) содержат ограничения и доказательства.
