# Тест-кейсы для приложения Жим-жим 21

Сценарии сверены с UI 8 сентября 2026 (O08); это ручной чеклист, а не отчёт об их выполнении. Используйте отдельный тестовый аккаунт и синтетические записи. [Запуск](README.md), [эксплуатация](../../docs/runbook.md).

---

## 1. Управление тренировками (Workout Logging)

### TC-1.1: Добавление нового подхода
**Предусловия:** Приложение открыто на главной странице. Список упражнений не пуст.
**Шаги:**
1. Выбрать упражнение в форме дневника.
2. Ввести вес (например, "60").
3. Ввести количество повторений (например, "10").
4. Нажать «Зафиксировать».
**Ожидаемый результат:** Новый подход отображается в списке за сегодняшнюю дату. Статус синхронизации меняется на «Синхронизация...», затем на «Синхронизировано».

### TC-1.2: Дублирование последнего подхода
**Предусловия:** В списке есть хотя бы один подход за сегодня.
**Шаги:**
1. Нажать «Повторить: …» под формой; тип последнего подхода должен оставаться доступным.
**Ожидаемый результат:** В списке появляется идентичный подход с тем же весом и количеством повторений.

### TC-1.3: Редактирование существующего подхода
**Предусловия:** В списке есть записи тренировок.
**Шаги:**
1. Нажать на иконку карандаша рядом с любой записью.
2. Изменить вес или количество повторений.
3. Нажать «Сохранить изменения».
**Ожидаемый результат:** Данные в списке обновляются. Статус синхронизации подтверждает сохранение.

### TC-1.4: Удаление подхода
**Предусловия:** В списке есть записи тренировок.
**Шаги:**
1. Нажать на иконку корзины/удаления рядом с записью.
2. Подтвердить удаление (если требуется).
**Ожидаемый результат:** Запись исчезает из списка. Общий объем (тоннаж) на странице статистики пересчитывается.

## 2. Управление типами упражнений (Settings)

### TC-2.1: Добавление нового типа упражнения
**Предусловия:** Перейдите в раздел "Настройки".
**Шаги:**
1. В блоке «Добавить тип тренировки» найти поле «Название упражнения».
2. Ввести название (например, "Подтягивания").
3. Нажать кнопку "Добавить".
**Ожидаемый результат:** Новое упражнение появляется в списке доступных типов при добавлении подхода.

### TC-2.2: Удаление типа упражнения
**Предусловия:** В списке настроек есть упражнения.
**Шаги:**
1. Нажать кнопку удаления рядом с названием упражнения в настройках.
**Ожидаемый результат:** Упражнение исчезает из списка. 
*Примечание: Существующие логи с этим типом упражнения должны сохраняться ; в истории название удалённого типа отображается как «Удалено».*

## 3. Статистика и графики (Stats)

### TC-3.1: Просмотр общей статистики
**Предусловия:** Наличие записей за несколько недель.
**Шаги:**
1. Перейти в раздел «Статистика → Обзор».
**Ожидаемый результат:** Отображаются общий объем, повторения, тренировочные дни за всю историю и средняя длительность. Тепловая карта показывает шесть месяцев; дни считаются в зоне профиля.

### TC-3.2: Фильтрация по типам упражнений
**Шаги:**
1. В «Статистика → Прогресс» открыть список упражнений.
2. Выбрать конкретное упражнение (например, "Жим лежа").
**Ожидаемый результат:** Графики прогресса обновляются для выбранного упражнения. Общий обзор остаётся статистикой всей истории.

### TC-3.3: Навигация по неделям
**Шаги:**
1. В дневнике тренировок нажать «Предыдущая неделя» (стрелка влево) в блоке истории.
**Ожидаемый результат:** Данные обновляются для предыдущей недели.

## 4. Синхронизация и Offline-режим

### TC-4.1: Работа в Offline режиме
**Предусловия:** Пользователь хотя бы один раз успешно вошёл на устройстве; затем интернет отключён.
**Шаги:**
1. Полностью закрыть и снова открыть PWA.
2. Добавить новый подход.
**Ожидаемый результат:** Приложение открывает локальные данные без сетевой авторизации. Подход атомарно сохраняется в IndexedDB вместе с outbox-записью. Индикатор показывает offline-режим.

### TC-4.2: Синхронизация после восстановления сети
**Предусловия:** Были добавлены данные в offline.
**Шаги:**
1. Включить интернет.
2. Дождаться автоматического восстановления аккаунта и синхронизации без перезагрузки; при ошибке использовать «Повторить подключение».
**Ожидаемый результат:** Локальные данные отправляются на сервер. Индикатор показывает «Синхронизировано», очередь пуста. При 429/временной ошибке данные остаются локально, повтор выполняется с задержкой.

### TC-4.3: Изоляция аккаунтов
**Предусловия:** На устройстве ранее использовались два аккаунта.
**Шаги:**
1. Войти в первый аккаунт и добавить локальную запись.
2. Выйти и войти во второй аккаунт.
3. Вернуться в первый аккаунт.
**Ожидаемый результат:** Второй аккаунт не видит и не синхронизирует данные первого; после возврата локальная запись первого аккаунта доступна.

### TC-4.4: Изменение во время синхронизации
**Шаги:**
1. Изменить сущность и запустить sync на медленном соединении.
2. До получения ответа изменить ту же сущность ещё раз.
**Ожидаемый результат:** Ответ первого sync обновляет базовую server version, но не удаляет более новое изменение из outbox. Второе изменение отправляется следующим запросом.

## 5. Публичные профили (Profiles)

### TC-5.1: Включение публичного профиля
**Предусловия:** Раздел "Профиль" в настройках.
**Шаги:**
1. Переключить тумблер "Публичный профиль" в состояние ВКЛ.
**Ожидаемый результат:** Появляется ссылка на профиль. Ссылка доступна для копирования.

### TC-5.2: Копирование ссылки на профиль
**Шаги:**
1. Нажать на сгенерированную ссылку или кнопку "Копировать".
**Ожидаемый результат:** Появляется Toast-уведомление "Ссылка скопирована". Ссылка находится в буфере обмена.

### TC-5.3: Просмотр публичного профиля
**Шаги:**
1. Открыть ссылку на профиль (в режиме инкогнито или другим пользователем).
**Ожидаемый результат:** Отображаются имя, доступный аватар либо заглушка, статистика за всю историю и последние 14 активных дней в зоне владельца. При разрешённой полной истории первая страница содержит до 100 подходов и «Загрузить ещё», если записи остались. Тепловая карта не ограничена текущей страницей истории; приватный профиль недоступен.


## 6. Длительность и резервная копия

Для типа «На время» заполнить часы, минуты и секунды, сохранить и отредактировать подход: секунды должны сохраниться. Сравнить длительность карточки и статистики с учётом пауз сессии.

В «Профиль → Данные» экспортировать JSON тестового аккаунта. Проверить merge офлайн, восстановление сети и sync. Replace доступен только онлайн; перед ним сохранить резервную копию. При конфликте ревизии импорт не должен частично менять данные.
